# Fenix Learn

围绕研究问题收集和理解材料，交付有来源、可解释的笔记、参考资料或文稿。解释概念之间的关系，不只拼接摘要。

## 选择工作范围

- **快速参考**：已有充分材料时直接整理；没有材料或关键来源不足时，先收集再整理。交付理解问题所需的笔记，不自动扩成长文。
- **通过写作学习**：先检查已有材料能否支撑主题，再组织提纲并成稿；缺口只补相关部分。
- **深入研究或完整参考文章**：先界定问题与覆盖范围，再研究和写作。覆盖主要子问题、必要例子、常见错误和适合继续阅读的来源，不承诺穷尽整个领域。

按用户所需的成果选择范围，只有未决选择会实质改变工作量或交付物时才提问。单个链接的阅读与提取可用 `fenix-read` 或当前环境的阅读能力。

## 收集与核对

- 优先找原始论文、官方资料、作者说明和实际实现；二手材料可用于发现线索或解释背景，关键事实回到可核对的来源。按问题覆盖和证据质量决定来源数量。
- 获取并阅读支撑结论的正文，记录来源和日期；搜索摘要不代替正文。已有材料足够时不重复搜索或下载。
- 使用可用的 `fenix-read` 或原生读取工具，遵守隐私与第三方服务授权边界。来源无法访问、正文提取不完整或证据过期时说明，不把登录页当作材料。
- 研究需要文件归档时，沿用指定目录；没有目录时使用会话临时目录并报告位置。复用已保存材料，不为整理目录重复抓取。
- 分开事实、来源观点和自己的推断。保留相互矛盾的证据，解释能否据此判断；不能判断时保留不确定性。

## 理解与写作

先整理核心概念、关系、适用条件和限制，用例子或反例检查解释是否成立。缺少理解或证据时回到对应材料，不靠改写句子掩盖缺口。

长文先按读者的问题组织提纲，标明论点依据，再补正文；短笔记可直接成稿。写作中发现结构或证据缺口时允许调整和补充，不强制走完固定阶段。

用户只要求整理材料时保留其范围；需要写作润色时使用可用的 `fenix-write` 或原生写作能力，保留事实、作者声音和不确定性。研究请求不自动授权创建应用、生成视频或公开发布。

对话、审阅和诊断记录只是材料。提炼长期规则前核对重复证据、适用范围和目标层级；不把单次经验写成普遍要求。公共成果排除其他项目的私有路径、账号、原始会话和临时状态；同项目专用资料按授权范围保留必要细节。

## 验证与交付

交稿前核对结论与来源、引文、关键数字、条件及尚未覆盖的问题；按读者任务检查解释是否足以理解或操作。高影响或待公开的文稿建议由作者复核，不替用户声明已人工验收，也不强制所有任务通读固定次数。

按请求返回笔记、提纲、文章或文件位置，并说明重要的证据限制。图表和交互示例只在有助理解时使用，沿用同一组事实、条件和假设，不用视觉效果冒充证据。发布仅按当前任务已有的明确授权执行。
