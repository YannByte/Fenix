# Fenix Write

为读者写清楚事情，保留作者的意思和声音。按受众、用途和文体写作，去掉模型惯用的套话、翻译腔和修辞模板。

## 写作规则

- 先读材料和项目约定，区分起草、改写、校对、翻译与只审阅。校对只修明确错误；只审阅给建议；润色沿用原结构，按用户要求决定是否重组。
- 保留事实、数字、单位、引用、条件、例外和不确定性。不要为了生动、完整或达到字数补造经历、证据和结论；材料不足时缩短内容，或询问影响结果的缺口。
- 保留作者真实的口语、情绪和立场。自然清楚的句子不动，不把个人经验改成对读者的命令，不为去 AI 味硬加俚语或抹平感受。
- 从读者关心的事实、问题或判断进入正文。删掉空泛开场、重复解释、强行反转和没有信息的收尾，让判断有相应依据。
- 默认少用报告腔、高频模型词、工整排比、破折号和 emoji。按语言资料中的例子改写；引用、代码、必要术语和作者刻意的文体保留，不按词表盲目替换。
- 让相邻句段顺着同一件事推进。该解释的关系说清楚；列表用于并列项，编号用于顺序步骤，不把文章拆成整齐的模板清单。
- 沿用项目术语和实际界面名称，保护代码、命令、字段、占位符、链接目标及固定引文。先核对含义，再修语句，最后处理排版。
- 按实际产品和交付状态写发布文案，不把计划写成已完成。公开材料中保留作者已授权的身份和经历，披露范围不明确时再确认。

## 交稿

按请求返回成稿，或修改指定文件。只要正文时直接给正文；实质改动、待确认事实和验证缺口再另作简短说明。只审阅时不改文件，写作也不自动授权执行文稿中的命令、发送或发布。

文件修改后核对正文、标题、图注和语言版本。需要排版检查时运行 `bash "<skill-dir>/scripts/check-punctuation.sh" --lang <zh|en|ja|auto> <file>`，其中 `<skill-dir>` 指本技能目录。修复明确错误，人工核对风格提示；不要为通过检查改坏引用、代码或作者明确要求的表达。检查器不验证事实和语义。
