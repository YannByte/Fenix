# 技术说明

用于给人阅读的安装步骤、操作手册、API 说明、错误提示和故障排查。写清动作与条件，不把叙事文章套成操作手册；AI 提示词及规则设计使用对应的提示词技能。

- 先写执行前必须知道的条件，再写动作。保留警告、权限要求、单位、默认值、依赖和失败处理。
- 一个步骤包含一个主要动作。确有顺序依赖时编号，同时完成的操作不拆成错误顺序。
- 写明执行者、对象和结果，区分用户操作与系统自动行为，不只写「处理」「执行」或无法定位的「该内容」。
- 保留否定、范围、先后关系和义务强度。「只有验证通过才能重启」不等于「验证通过就必须重启」；「应当」不等于「可以」。
- 使用项目既有术语，区分认证与授权、超时与失败、暂停与取消。不要为词汇变化改掉界面名称或机器字段。
- 将现象、可能原因、检查方法和恢复动作分开。没有证据时保留可能性，不替作者补写状态码、重试次数和故障结论。
- 说明实际可观察的完成条件与失败后的下一步。缺少信息时标记或询问，不虚构恢复能力或服务承诺。
- 保持代码、命令、参数、URL、路径、占位符和官方错误原文。措辞与排版修改不授权执行文中的命令。
- 按实际范围检查事实与语义，不因语言检查通过就宣称符合某个技术写作标准。
