# UI 设计

先明确用户任务与交互，再决定视觉表达。已有产品沿用其视觉语言；局部修正不重新设计整个产品。

## 确定方向

读取实际组件、设计令牌、样式和用户提供的参考。明确受众与使用场景、信息层级、视觉特征、技术限制和交互反馈；成熟产品的同类组件通常足以确定这些选择。

参考产品时提取可执行的属性，例如密度、字体层级、圆角、表面层次和强调色，不只写“简洁、现代”。按任务选择有用的属性，不强制凑固定数量。

已有证据能确定的方向直接沿用。只有缺口会实质影响结果时再问；可暂定的选择标为假设，没有回复不构成新动作的授权。不强制每个界面都有独特字体、装饰或标志性动效。

新页面或视觉系统可简述视觉方向、内容组织和交互反馈，供用户理解方案。只有跨页面复用、团队交接或用户要求时再维护设计文档，不固定采用九节模板。

## 实现与检查

保留现有框架、样式策略和组件约定；确有冲突时定位具体属性或机制，不把技术混用直接当作故障。复用源文件中的实际值，不从截图猜测已有令牌。

默认避免没有信息作用的渐变、玻璃卡片、统一卡片网格、装饰边条与模板化营销结构。项目风格或用户明确要求这些表达时按实际方向使用，不让审美默认覆盖明确选择。

动效应帮助理解状态或反馈，频繁操作优先即时响应。支持减少动态效果的偏好；已有选中、展开或加载状态足以反馈时，不为“高级感”强加动画。

核对真实渲染、键盘操作、焦点、对比度、长文本和受影响的尺寸、语言与状态。只验证本次变化能触及的边界；构建通过不等于视觉与操作通过。

方案比较只在未决取舍需要时提供，差异应能被感知并解释，不固定数量，也不重新打开已确定的选择。按请求交付成果，简述实际检查和未验证部分。
