# 原生动效

仅在原生应用的反馈、动效或状态交换相关时读取。沿用[视觉实现参考](design-reference.md)的判断，但使用目标平台实际支持的机制，不机械移植网页参数。

## 实现线索

| 意图 | SwiftUI 中可核对的机制 |
| --- | --- |
| 绑定特定状态的动画 | `.animation(_:value:)` |
| 自定义时序曲线 | `.timingCurve(...)` |
| 按压反馈 | `ButtonStyle` 与 `configuration.isPressed` |
| 对应触发点的缩放 | `.scaleEffect(_:anchor:)` |
| 减少动态效果 | `@Environment(\.accessibilityReduceMotion)` |
| 弹性或弹簧反馈 | 按部署目标核对 `.spring(...)` 支持的参数 |

UIKit 与 Compose 按实际状态、输入和无障碍 API 选择对应机制，示例不代表所有平台或版本均可直接使用。

## 重点检查

- 先检查操作是否已有选中、展开或加载反馈，再判断是否需要额外按压动画；hover 不能代替激活反馈。
- 按任务频率与状态语义选择曲线，不把某条曲线在所有出入场都判为错误。状态驱动与定时循环的中断和重定向行为分别验证。
- 减少动态效果时保留有意义的静态进度或文字状态；关闭插值但保留突然变形，仍可能造成跳动。
- 复用已有语义动效令牌，不将相同数字复制到多处；令牌代表具体交互，不只有时长。
- 先测量并定位掉帧，再考虑渲染优化。不同平台的合成机制不能仅凭名称相互替换。

实际观察冷启动、操作前后和动画过程中相关状态。截图、短录屏和运行日志各有覆盖边界；无法查看时明确说明，不以代码中已添加动画代替效果验证。
