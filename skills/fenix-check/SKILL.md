# Fenix Check

审阅当前改动及其影响，给出有证据的问题或交付结论。审阅、审计和就绪检查本身不授权修复、提交或对外操作。

## 确定范围

先运行 `git status --short --branch -uall`，按用户要求确定基线：未提交改动包含暂存、未暂存和未跟踪文件；分支或 PR 使用合并基线至目标提交；发布审阅以实际分发渠道的上一版本对应源码为准。整库审计走专项流程。

记录基线、HEAD 和改动清单，读取项目规则、验证入口及相关调用方。保留用户工作，不擅自切换当前分支、藏起、移动或清除文件；需要干净环境时使用隔离工作树。修复或仓库状态变化后，刷新审阅范围并重查受影响结论。

## 审阅规则

- 检查改动是否满足请求、是否遗漏必要资源，以及是否引入没有实际用途的依赖、配置、抽象或行为。已明确接受的方向不反复争论。
- 沿输入、调用方和下游结果检查正确性、错误处理、数据完整性及兼容性。修复模式可能重复时，核对同类位置，不把搜索命中直接认定为故障。
- 涉及认证、凭据、命令构造、路径、删除、安装、更新或发布时，检查输入边界、权限、影响范围和失败恢复。深度由实际风险和项目要求决定，不由行数或文件数单独决定。
- 每个问题说明触发条件、用户或系统影响、具体位置及证据。核对现有保护和设计意图；区分本次引入与既有问题，不把猜测列为已确认缺陷。不必为凑报告制造问题。
- 只在已有修复授权内改动；授权覆盖必要的行为修复，不再按修复类别重复询问。范围扩大或有未决产品取舍时再确认。
- 用户已授权审阅通过后的提交或推送时，完成审阅、修复和验证后继续执行对应动作。新增未解决风险超出原授权时说明影响，不带着问题直接宣称可交付。

## 验证与交付

使用项目声明且适合本次改动的验证命令。入口不明时先查文档、清单和 CI，也可从目标项目根目录运行 `bash "<skill-base-dir>/scripts/run-tests.sh"` 辅助发现；`<skill-base-dir>` 指本技能目录。没有找到命令是证据缺口，不能当作通过或产品故障。

区分环境准备失败、断言失败、跳过与实际通过。确认检查执行了非空的目标路径；测试不能覆盖的运行或安装行为需另行核对。回归保护应能检出旧故障，不以更新快照代替独立预期。其他未提交工作可能影响结果时，在隔离环境验证本次补丁。

只报告实际取得的证据；复用结果时注明对应版本、输入及仍然适用的依据。需要核对 CI 时读取结构化状态和结论，不用截断输出掩盖退出状态。发布就绪还需检查项目要求的版本、生成物、包内容和实际分发结果；只提交或推送不强加发版流程。

按影响排序报告问题，再简述审阅范围和验证限制；没有发现问题可以直接说明。交付任务另报实际提交、远端、CI 或发布状态，仅列相关项。多个事项逐项交代完成、剩余或受阻状态，不固定附加统计表。委派审阅时核对返回结果与覆盖范围，未完成的部分不能算已审阅。
