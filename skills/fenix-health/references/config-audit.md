# 配置与信任边界

先核对采集器的配置摘要与当前宿主支持的功能；具体语义不明时查对应版本的官方说明或做只读验证。

## 指令与配置

- 核对全局、项目、嵌套文件和本地覆盖的实际加载关系。配置摘要是静态线索，不从固定文件名推定所有宿主都读取它。
- 只有规则互相矛盾、重要约束不可达或稳定项目规则只存在于私有覆盖文件时，才报告相应问题。缺少某种文档或信任键本身不足以证明配置失效。
- 记录来源、启用状态、实际执行路径和未检查的上级或嵌套范围。缺失 Hook／MCP 可执行文件与服务连接失败分开报告。
- Hook 看似未触发时，先查执行记录和输出是否被后续界面遮挡，再判断是否需要修改配置。

## 权限与外部执行

- 区分指令决定“何时允许做”和权限层决定“是否再次询问”。用户刻意允许已授权的常规推送不自动构成漏洞，不擅自收紧其配置。
- 按实际风险检查凭据读取、打印、提交和外传边界，以及删除、覆盖和远端写入的控制。明确用户已选择的取舍；只在控制确实缺失或被绕过时报告，不将个人推荐当作项目强制要求。
- 宿主没有命令拒绝表时，不推荐虚构的 deny 键。命令前缀、进程限制和文件边界作用不同；检查匹配层再判断影响，例如直接禁止 `ssh` 命令不等于禁止 Git 内部的 SSH 传输。
- 字符串 Hook 可能误伤引文或 heredoc；通配规则也不能可靠解析管道。说明覆盖与误报限制，不声称词法拦截能解决全部执行风险。
- API 地址覆盖、通配工具授权、自动信任和跳过权限检查都是调查线索。先核对项目用途、目标与已有授权，再判定具体风险；报告键名和位置，不打印敏感值。

## 记忆与第三方来源

检查记忆中是否有凭据、过期规则或不可信输入写入的指令。当前证据与既有记忆冲突时重新核对，不让记忆授予工具权限；高风险输入是否允许持久化由当前任务与配置决定。

核对技能、插件和 MCP 的来源、版本或提交、Hook 行为及服务信任设置。浮动来源意味着更新内容可能改变，按实际更新机制说明风险，不将未固定版本直接当作已被利用。重点检查是否有未授权的外部执行或凭据写入。

## 报告

每个问题需有具体状态、风险和下一步；检测到凭据时隐藏内容，并根据暴露范围建议处置。全局配置问题只报告一次；明确授权修改时先重新读取最新文件，避免覆盖其他会话的工作。
