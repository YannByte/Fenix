# 中文写作

先保留原意、事实和作者声音，再去除模板腔，最后处理排版。下面是默认取舍，用户要求、项目规范、固定引用及作者刻意的文体优先。

## 去 AI 味

- 直接进入问题、场景、事实或判断。删去「随着……的发展」「本文旨在」「值得注意的是」等不提供信息的开场。
- 一个观点在合适的位置说清楚，后文补充证据或新的含义。不要反复总结、逐行复述表格，或在段末替读者补一句大道理。
- 从正面说出判断，少用没有材料支持的「不是……而是……」「你以为……其实……」。真实对照、条件边界和作者的自我修正保留。
- 打散机械排比、固定的小标题句型和问答式起手。保留真正并列或有顺序的内容，不按固定项数凑清单。
- 默认不用破折号和 emoji 制造强调，少加引号、括号、感叹词和省略号。先理顺句子，再选择逗号、句号或冒号；必要括注、固定引文和作者刻意表达保留。
- 不为「像人说话」补上俚语、比喻和口头禅，也不把作者已有的口语、情绪和真实感受改成中性报告。
- 避免装饰性的具体细节。经历、数字、参数、故障原因和原话须来自材料，不能为了工程感或画面感编写。
- 用具体对象和动作解释抽象概念。删除多余修饰和空泛判词，保留确有含义的限定，不把含蓄表达一律改成直白结论。

## 默认用词

结合上下文去掉左栏的模型习惯，不要求逐字替换。正式文书、界面名称、技术术语和引文按实际用途保留。

| 常见写法 | 改写方向 |
| --- | --- |
| 值得注意的是、综上所述、核心结论是 | 直接写事实、判断或结束正文 |
| 赋能、抓手、闭环、底层逻辑、全链路 | 说明谁做了什么及实际影响；没有材料就指出缺口 |
| 例如、使用、购买 | 普通叙述中可用「比如、用、买」，正式场景不强行口语化 |
| 非常、极其、不可或缺、事半功倍 | 删掉无依据的强调，或写明程度与依赖关系 |
| 接住观点、击穿论证、锋利的判断 | 用「理解、反驳、不成立」等贴合实际含义的表达 |
| 你会发现、你必须先明白 | 直接说明事情；必要的操作指令保留 |
| context、state、cache 等已有通行译法的词 | 默认用「上下文、状态、缓存」，标识符和官方名称不翻译 |
| 最好的、开箱即用、一句话搞定 | 写清可验证的能力、前提和限制，保留有依据的承诺 |

## 句段与文体

- 让读者尽早知道谁做了什么。拆开层层定语、含糊指代和混杂话题，保留必要的因果、条件与取舍。
- 一段围绕一个主要意思，让下一句接续已经出现的人、物或结果。顺畅的长句可以保留，不按字数切句，也不把短句硬并成长句。
- 连词按作用取舍，保留真实的转折、顺序和因果，只删机械过渡。列表用于比较和并列项，论证与经历用自然段。
- 技术说明写准确清楚，必要步骤可用祈使句；文章和个人叙述按作者口吻展开，不把探索写成专家训话。
- 公开文案先写读者关心的变化，不靠贬低同类产品衬托自己。客观比较保留有证据的差异和适用条件。
- 图片、表格和正文各自提供信息。核对图中文字、图注、替代文字和正文，保留独特材料，不为视觉对称补图或补段。

## 术语与排版

- 同一概念沿用一个首选术语，优先采用项目和产品实际用法；不要为了变化改名。首次解释以读者需要为准，避免每个术语都堆括注。
- 中文正文用全角标点，默认用直角引号「」和嵌套引号『』；中文说明用全角括号，作品名用书名号。项目、地区和固定引用规范可以覆盖。
- 中文与英文、数字、版本号和行内代码之间留一个半角空格，按可见文字判断链接边界。全角标点前后不额外留白，不改代码和链接目标内部内容。
- 数字与半角单位符号之间留空格，如 10 GB、200 ms、25 °C；百分号与角度符号紧邻数字，如 50%、90°。保留原数值、精度和单位。
- 需要保留中文省略号或破折号时，使用「……」「——」；命令选项和 Markdown 标记不受影响。合法用法即使被检查器标记，也需按语境判断。
- 中文 Markdown 段落在源文件中保持一段一行，保留代码块、表格、引用块、HTML 和显式换行的结构。

交稿前连着上下文回读，检查删改是否丢失信息、削弱情绪或改变确定程度。排版检查不能代替这一步。
