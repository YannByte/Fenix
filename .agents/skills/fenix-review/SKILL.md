# Fenix 仓库审阅

读取[仓库规则](../../../AGENTS.md)和[开发流程](../../../docs/development.md)。先运行 `make scope PYTHON=.venv/bin/python` 盘点实际改动；明确用户要求的基线，再检查对应差异、调用方和测试。盘点结果不代表已完成审阅。

- 技能改动：检查触发条件、任务边界、前置能力和完成标准；目录名、元数据、跨技能引用和清单应一致。规则语言的机械校验不能证明模型行为。
- 脚本改动：检查参数、失败出口、写入范围、可选依赖和独立安装后的资源定位；用合成输入验证实际失败路径。
- 交付改动：区分公开技能与项目工作流，检查许可证和来源引用；安装入口需覆盖首次、重复、冲突和中断失败情形。
- 新增检查：确认有效输入通过、无效输入失败，不能只对照代码实现编写预期。

使用 [fenix-verify](../fenix-verify/SKILL.md)选择验证范围。只报告能说明触发条件和后果的问题，附当前文件位置；区分本次引入和原有问题。审阅本身不授权修复或发布评论。报告审阅范围、实际检查及未验证的行为，证据留在会话中。
